# AEGIS — Model Metrics

Generated by `scripts/write_metrics_doc.py` from the JSON emitted by the training
scripts. Do not edit by hand; rerun the generator.

## Read this first

Every figure here comes from **synthetic data**. The transaction ledger was generated
because no public dataset carries device fingerprints and IPs linked across a customer's
order history — without which CE 3.0 qualification cannot be computed at all, let alone
evaluated. Outcome labels were drawn from a documented structural model, so training a
model to recover them is **partly circular**.

Three things bound that circularity:

1. A per-issuer random effect that is never exposed as a feature to any model.
2. A deliberately large residual noise term in the outcome draw.
3. Customer-grouped splits everywhere — no customer appears in two splits.

**These metrics measure whether the pipeline recovers a known structure under noise.**
They are not external-validity claims. Validation on real dispute data is the next step.

## Side A — CE 3.0 qualification and win probability

The qualification gate is a **rulebook, not a model**: it is exact, and its correctness is
a matter of reading the Visa criteria properly rather than of accuracy. What is modelled
is the win probability conditional on qualification.

| Metric | Value |
|---|---|
| Test cases | 650 (unseen customers) |
| Base rate | 19.7% |
| ROC-AUC | 0.745 |
| PR-AUC | 0.422 |
| Brier, uncalibrated | 0.1464 |
| Brier, isotonic-calibrated | 0.1358 |

PR-AUC 0.422 against a base rate of 19.7% is roughly a
**2.1× lift**. It is not higher because the generative process carries a hidden
per-issuer effect and a large noise term that no model can see — deliberately, so the
number reflects a hard problem rather than an invertible formula.

| `qualified` | 159 | 47.2% | 46.6% |

## M3 — Genuine-intent classifier

Test cases: 650. Macro F1 **0.562**, accuracy 60.8%,
log-loss 0.8360.

| Intent | Precision | Recall | F1 | OvR ROC-AUC | Base rate |
|---|---|---|---|---|---|
| `criminal_fraud` | 0.264 | 0.453 | 0.333 | 0.758 | 13.9% |
| `first_party_misuse` | 0.762 | 0.559 | 0.645 | 0.712 | 61.9% |
| `genuine_service_failure` | 0.639 | 0.793 | 0.708 | 0.852 | 24.2% |

Trained with balanced class weights. Unweighted, `criminal_fraud` scored **0.000 precision
and recall** — the model ranked it at 0.72 ROC-AUC but the majority classes always won the
argmax. The costs are not symmetric: predicting first-party misuse for a cardholder whose
card was genuinely stolen means pursuing a fraud victim. Accuracy fell from 0.665;
macro F1 rose to 0.562.

This model also consumes Side B's **out-of-fold** tamper score. Using in-sample forensic
scores would have made the feature sharper here than it can ever be in production; see
`scripts/score_evidence_oof.py`.

## Cost, not accuracy

No threshold in this system is chosen by F1. The Cost Lab sweeps policies against the
held-out set in rupees and reports the confusion matrix in rupees, because the cost of a
false positive here is a real fight fee spent on a case that loses. See the Cost Lab page
in the console for the live sweep against your own economics.
